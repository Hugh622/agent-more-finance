# 部署與運維要點（數據管道腿·全棧開發）2026-10-11

> 本文件是三地行情抓取管道在**本雲端環境**落地運行三個月的實戰運維提煉，供外部評審了解系統真實運行方式與脆弱點。配套自愈清單見 `HEARTBEAT_自愈清單.md`。

## 1. 架構：無 OS 級調度器的守護進程方案

本環境**沒有 crontab / systemd**，調度完全靠「setsid 守護進程 + 心跳自愈清單」：

| 守護 | 啟動命令 | 職責 |
|---|---|---|
| `scripts/scheduler.py` | `cd <管道絕對路徑> && setsid nohup python3 scripts/scheduler.py > logs/scheduler.out 2>&1 < /dev/null &` | ah_eod：A股/港股工作日 16:40 全量收盤抓取；us_morning：每日 06:30 美股收盤抓取 |
| `scripts/spcx_monitor.py --loop` | 同上，用 `spcx_monitor.py --loop` | SPCX 量價基線監控，周二~周六 06:50 |

**已知致命弱點（評審重點）**：守護進程是環境易失資產——環境重啟即靜默消失。三個月內**四次事故**：9/12（死亡致 FOMC 週數據缺口 7 天）、9/19、9/28、10/6–10/9（三天空窗，10/9 發現後重啟＋全量回填）。唯一保險是心跳輪詢＋自愈清單。**建議**：改用外部看門狗（systemd/supervisor/雲函數心跳）或至少獨立進程監控告警。

## 2. 操作鐵律（血淚教訓）

1. **重啟必須絕對路徑**：`cd <絕對路徑> && setsid nohup ... &`——後續命令不繼承 cwd。
2. **504 之後先 `ps` 再重試**：504 報錯時命令可能已實際執行，盲目重試會造成並發批。
3. **永遠單寫者**：並發批會互相覆蓋文件＋觸發限流。所有寫入收斂到調度器單點。
4. **限流冷卻**：被風控後恢復要等 900 秒級冷卻，不要熱重試。
5. **薄數據自查**：K 線行數 < 100 即標 thin 重拉（來源偶發截斷）。
6. **環境回顯損壞**：本環境的工具回顯可能混入其他文件內容或亂碼——**寫入後必須乾淨讀回複核；數字只信源數據直讀（CSV/JSON），不信回顯**。
7. **SPCX 斷檔補救**：`scripts/spcx_monitor.py --force` 手動補檔實測有效（滾動窗口可回填）。

## 4. 代碼映射陷阱

- 港股：02269=藥明生物、02268=藥明合聯、02359=藥明康德（三地共振貼線期**切勿混**）
- 美股後綴：`.OQ`=NASDAQ、`.N`=NYSE、`.AM`=AMEX；新入池標的**勿信 .OQ 優先探測**（10/10 年檢 16 只誤鎖 .OQ 教訓，修正流見 `02_年檢數據作業/fix_suffix_refetch.py`）
