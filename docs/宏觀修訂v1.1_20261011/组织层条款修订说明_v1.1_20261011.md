## 一、五项修订逐条对照

### 修订① 腿间分歧处置：条件化表态前置 → 盲审信封制

| | 内容 |
|---|---|
| **原文（v1.0 三-1）** | 腿间分歧：先发「条件化表态」（声明不背书）→ 候首席仲裁 → 避免沉默误导终裁 |
| **修订后（v1.1 三-1）** | 高风险决策走**盲审信封制**：各腿结论**封存提交**（结论文档私发首席，群内只报「已交付」；数据快照层全员可见互证）；**解盲前禁止在群内披露己方方向性结论、禁止对他腿结论文风表态**。首席收齐信封后统一**解盲**；解盲后如现分歧，才进入「条件化表态」→ 候首席仲裁 |
| **修订理由** | 原流程「条件化表态前置」＝提前暴露己方结论。群聊是全透明介质，先发声的腿会污染其他腿（叙事预装/从众），使交叉核验退化为互相印证——与盲审目标直接冲突。「条件化表态」不废除，改为**解盲后**的分歧处置工具 |
| **操作成本** | 零工具成本：信封＝群内文件私发首席＋群内仅报完成；不迁移平台 |

### 修订② 核验规则新增第 7 条：签名快照制

| | 内容 |
|---|---|
| **原文（v1.0）** | 核验规则仅 6 条，止于「行情快照双源+时间戳」；研究腿引用数据无溯源强制要求 |
| **修订后（v1.1 第 7 条）** | 数据腿对每次供数产出**签名快照＋品质评分**：快照含 snapshot id、采集时间戳（UTC+HKT 双记）、来源与等级、字段口径、sha256（**与 Manifest v2 字段对齐**）；品质评分标注完整度/双源状态/已知缺口。**研究腿引用数据必须指向 snapshot id**，禁止凭记忆、转述或无溯源读数引用 |
| **修订理由** | 「多腿同源盲区」是量化腿自认第 5 短板：各腿从同一坏数据各自推出自洽结论，事后无法定位错在数据还是推理。签名快照把**数据与结论分离追溯**——同源同错可检、责任可定位 |
| **落地依赖** | Manifest v2 在全栈 P1 清单内；落地前以「快照文件名+hash」过渡，不阻塞本条生效 |

### 修订③ 《团队框架总览》管线图改双轨制

| | 内容 |
|---|---|
| **原文（v1.0 三）** | 单轨：各腿并行 → 交叉核验（跨腿互证读数；分歧先发条件化表态再候仲裁）→ 首席终审 |
| **修订后（v1.1 三）** | **双轨**：├ **数据层互证（保留）**——读数快照互证、snapshot id 溯源、分歧标注，快照全员可见；└ **结论层隔离（新增）**——进场/仓位/规则变更走盲审信封制，结论封存私发首席、解盲前各腿互不可见（例行作业不适用）。终审环节相应更新为「解盲 → 分歧走条件化表态+仲裁 → 看板定稿」 |
| **修订理由** | 数据互证与结论盲审是两种不同质量的机制：数据错要尽早暴露（透明有利），结论错常源于互相污染（隔离有利）。单轨制把两者混在「全透明」里，只保住了前者 |
| **连带修改** | 管线图首环节各腿产物标注更新（宏观腿加 thesis/invalidation、全栈腿加签名快照）；演进史表新增「组织层 v1.1」行 |

### 修订④ 宏体验收边界升级：thesis＋invalidation 完整性检查＋时间证伪条款

| | 内容 |
|---|---|
| **原文（v1.0 三-2）** | 宏观侧验收仅司数值自洽+叙事兼容，不作数据真实性背书（真实性归首席/量化/全栈链） |
| **修订后（v1.1 三-2）** | 原数值边界**保留**；新增两条：**（a）完整性检查**——每份腿级报告必须预定义 thesis（可证伪的判断句）＋invalidation（可观察、带数据锚的证伪条件），禁止只写方向；无 invalidation 的报告不进入首席统合。**（b）时间证伪条款模板**——每条 thesis 必须绑定时间锚「**X 月底前未发生 Y 即作废**」，三要素＝时间窗＋可观察事件＋数据源锚；invalidation 一律绑定事件日历节点作检查点（如 TIC 10/16、CPI 10/14、FOMC 10/27-29） |
| **修订理由** | Bull/Bear＋权重表的两面证据各自可自圆其说、没有「错」的定义，复盘无法归因；宏观叙事抗证伪性最强（利率/地缘可无限重构解释），预写证伪条件是防叙事漂移的唯一硬闸。模板示例：「『加息防守』主轴若 12/1 前未出现『12 月加息概率持续 ≥60% 或 10Y 三日收于 5.05% 上方』即作废，转中性」 |
| **适用范围** | 本条为宏观腿验收自加码，同时作为全队腿级报告的推荐范式（不强制他腿） |

### 修订⑤ 分级盲审适用原则成文

| | 内容 |
|---|---|
| **原文（v1.0）** | 盲审无分级，隐含全场景适用——日度扫描也走全流程会令时延倍增 |
| **修订后（v1.1 三-5）** | 三级适用表：**全盲审**＝进场决策、仓位调整、规则/框架变更、L4 年检终审类（信封制全程）；**半盲审（快照互证）**＝重要事件研判、多腿合著专题（快照全员可见、结论文档延迟披露，首席统合后统一发布）；**不适用**＝日度扫描、例行数据作业、档案整理、每日简报（维持现行流程） |
| **修订理由** | 盲审收益与决策不可逆性成正比、与时延成本成反比。日度扫描无决策增益，强行盲审纯属流程税；不写清楚分级，「信封制」会被滥用到例行作业上，一周内就会形同虚设 |

## 二、保留不改声明（v1.1）

以下条款经 2026-10-11 外部评审评估后**明确保留、不修改**：

1. **L0-L3 仓位天花板**（🟢≤75% / 🟡≤60% / 🟠≤40% / 🔴≤20%）维持不变。外部评审提出的压力测试、风险贡献、因子暴露、drawdown policy 等动态风险指标，列为**实盘准入条件**——实盘前必须建成，纸面阶段不加重流程
2. **CPI / FOMC 双裁决点前禁进场**维持不变（当前锚：10/14 CPI、10/27-29 FOMC）
3. 台账唯一主档制、判例库（3 条在册）、AI 主题仓状态机 v1.2、金链双确认解禁条件维持不变
4. **群聊为协作介质不变**：盲审信封以「结论文档私发首席＋群内仅报完成」实现，不迁移工具、不引入新平台
5. **数据预算不扩编**：finnhub key 用户兜底、GitHub PAT 沿用、付费港股第二源不采用（用户 2026-10-11 裁定）；本机制不因外部评审自动扩编成本
