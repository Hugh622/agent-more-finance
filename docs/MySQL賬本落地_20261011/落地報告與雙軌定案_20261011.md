**兩個關鍵適配發現（已寫入 DDL 與腳本）：**

1. **5.7 方言**：排序規則用 `utf8mb4_unicode_ci`（無 0900 系列）；CHECK 約束 5.7 會解析但忽略，改用 ENUM＋應用層；JSON 類型可用（5.7.8+）；`signal` 是 MySQL 保留字，須反引號。
2. **連接復用代理行為**：`SELECT @@variable` 與 `SET SESSION` 類語句會被代理直接重置連接（實測）。因此**全庫 UTC 存儲改為應用層約定**（ledger 服務寫入前統一換算 UTC，`as_of_tz` 欄保留原時區），字符集由表級 DDL 強制，不再依賴會話變量。

### 「SQLite vs MySQL」雙軌定案

| 層 | 定案 |
|---|---|
| 事實主檔 | **MySQL（CynosDB）唯一事實主檔**（ledger of record）。理由：實例已授權可用、多端讀取一致性、徹底消除 .db 檔入 Git 風險（評審禁放清單自然滿足） |
| SQLite | **降級為本地測試 fixture**（單測/CI 用同構 schema 轉譯版）＋管道本地緩存。**不做雙寫、不做同步** |
| Markdown 台賬 | 閱讀視圖（原共識不變），由 MySQL 生成，不再作事實來源 |
| 原過渡方案調整 | 原「雙軌並行兩週再切」取消，改**分階段收編**：第一期（即日）凍結層＋註冊冊四表生效（instrument_master/market_snapshot/rules/signal）；第二期隨 Paper Trading v2 引擎收編 order→fill→lot→decision→experiment。切換期 Markdown 仍雙軌顯示，**數據以 MySQL 為準** |
| 寫入通道 | 單寫者原則不變：一律經全棧單一 ledger 服務寫入，其他腿只讀；斷網時降級本地 append-only JSONL 排隊補寫＋每日本地冷備 SQL dump（憑據同樣僅環境變數注入） |
