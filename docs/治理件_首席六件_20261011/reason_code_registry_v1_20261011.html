设计原则（三条）： ① 判例锚定制——每类必须挂现行判例库在案判例，无判例不立码；② 机检优先——每类给出可机检触发特征，供五闸审计器/覆盖矩阵校验器直接消费；③ 主辅码制——复合事件按「最初触发原因」定主码、处置结果定辅码，一单最多一主一辅，防编码爆炸。

三、人工 Override 全记录机制 v1.0

3.1 覆盖范围（三类必记）

① 用户明示破闸/裁定（如三项用户裁定）；② 首席终审改判（仲裁、勘误、规则改判）；③ 紧急风控手工干预（事件窗跳过流程类动作）。未入记录的 override 一律视为无效决策，五闸审计器可拒认。

3.2 台账字段（override_log 最小七列）

字段说明
override_idOV-日期-序号（如 OV-20261011-01）
object被改对象：规则/仓位/标的/流程，带原值→新值
reason_code主码（多为 HUMAN_OVERRIDE，也允许其他主码）
decider决策人：用户／首席／（紧急时）当值腿
rationale理由分类：用户裁定／首席改判／紧急风控，附一句话依据
validity有效期：一次性／限期（到期自动失效）／永久（须附复检日）
review_due复检日；到期未复检的限期项在周检自动亮红

3.3 分析节奏（并轨条款）

每三个月做一次 override 增值分析：统计频次分布、破闸率、事后胜率；与现行「判断 vs 恐惧截胡」行为复盘并轨——凡属用户侧 override，逐条标注「判断问题（正面记录）／恐惧截胡（行为标注）／合理审慎（不扣分）」三分法，产出行为模式季度报告。此节奏与外部评审「override 三个月增值分析」要求合并执行，不另立会议。
