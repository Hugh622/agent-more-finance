## 1. 升級範圍與根因

| 項 | v1.0.1 | v1.0.2 |
|---|---|---|
| MySQL 方言 | @var 同批自引用（SET 前置/後置均取不到同批 INSERT 父行 → supersedes 全 NULL） | **兩段式閉鏈**：stage1 INSERT 全量 NULL → stage2 逐鏈 UPDATE..JOIN 閉合；@var 全面廢除（CynosDB 代理重置 SESSION 變量風險歸零） |
| SQLite 方言 | 多行 VALUES 內標量子查詢引用同語句先前插入之行——**實證同樣靜默落 NULL**（復現腳本在案） | 同構兩段式：stage1 INSERT 全量 NULL → stage2 逐鏈 UPDATE 標量子查詢閉合 |
| 三硬斷言 | 「鏈閉合零懸掛」空轉通過（0 鏈≠0 懸掛） | A1 鏈數==registry 聲明數（=3）；A2 無懸掛／無自引用／父版本嚴格更低（生成期真 semver 斷言＋SQL 側雙保險網）；A3 每鏈 UPDATE rowcount 精確==1、合計精確==3（生成器內嵌＋builder 程序化捕獲） |

**關鍵認知修正**：v1.0.1 缺陷非 MySQL 獨有——同批自引用閉鏈在兩方言同構失效，任何「內聯/變量式」閉鏈寫法都不可靠，兩段式是唯一跨方言穩健修法。

## 5. 過程中修掉的第二處隱患（記錄在案）

builder 逐語句執行種子時，`sqlite3_complete` 會把純註釋塊與其後語句合併為同一 buffer；若按「語句開頭」匹配 UPDATE 捕獲 rowcount，整段會被靜默跳過——**又一種空轉通過形態**。已改為「剝離整行註釋後執行＋閉鏈 UPDATE 內容檢測捕獲」，教訓與「0 鏈≠0 懸掛」同類：**斷言必須斷在正被驗證的對象上，而非其影子**。
